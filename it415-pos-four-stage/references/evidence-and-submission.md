# Evidence and Submission

Read this reference during Stage 4, before version-control actions, and during final readiness checks.

## AI-assisted development evidence

The exam requires at least two separate documented AI prompts used at different development points. For each actual prompt, preserve:

1. Exact prompt text.
2. Purpose of the prompt.
3. AI response summary or screenshot.
4. Student evaluation: correct, partially correct, or incorrect, with a reason.
5. Modifications the student made before using the output.

The form says to fill it while working. Produce a completed four-stage record after each cycle so the student can transfer truthful information into the form. Never invent an earlier prompt or modification to satisfy the minimum count.

## Application screenshots

Capture clear, readable evidence from the running application for:

- Product list/order screen with product names and prices.
- Cart/order summary with items, quantities, subtotals, and total.
- Successful payment with computed change. A rejected-payment screenshot is encouraged but optional.
- Receipt with items, total, amount paid, change, and transaction reference.

Do not treat source-code inspection or a mocked image as proof that the application ran.

## Git and GitHub evidence

The repository is expected to show:

1. A repository for the application.
2. An initial commit for project setup and the basic interface.
3. A commit for core ordering and computation: cart, totals, and change.
4. A commit for validation, debugging, and final improvements.
5. A successful push to GitHub.
6. Visible commit history plus a brief README or short project documentation.

Advanced branching, pull requests, and merges are not required. Keep commit messages aligned with actual changes. Do not rewrite history merely to manufacture the expected timeline. Create commits or push only when the user's request authorizes those actions.

## Final readiness check

- [ ] One complete transaction follows the required flow.
- [ ] All twelve required features work.
- [ ] At least two real prompt records are ready.
- [ ] Required application screenshots are captured from the running app.
- [ ] Commit-history evidence is captured.
- [ ] Source code, GitHub repository link, AI documentation, and screenshots are ready to submit.
- [ ] The student can explain the main functionality and any AI-assisted code.
- [ ] The declaration and personal fields remain for the student to review and complete personally.

The official DOCX form is the submission document. This reference is a checklist, not a replacement for that form.
